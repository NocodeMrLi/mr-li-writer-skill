# 文章开头设计规范

## 目标

开头决定读者是否愿意继续读。好的开头不是固定套路，而是根据主题、材料、体裁、平台和读者状态设计出来的入口。

本规范要避免两类常见 AI 腔：

1. 反复使用虚拟来源开头：如“后台有人问”“群里有人问”“每到这个时候网上就有人问”。
2. 反复使用数据或定义前置：如一上来“数据显示”“根据报告”“所谓 X 是……”。

虚拟提问、场景叙事和数据前置都不是绝对禁止，但必须服务于当前文章，并且不能成为默认开头。

## 一、开头设计前先判断

写正文前，先内部确认：

| 字段 | 要回答的问题 |
|---|---|
| 读者入口 | 读者是带着问题、焦虑、好奇、情绪、选择还是搜索意图进来的？ |
| 文章体裁 | 政策解释、实用指南、观点评论、关系生活、故事特写还是产品分析？ |
| 最强材料 | 当前材料里最适合开头的是事实、场景、冲突、判断、动作还是问题？ |
| 风险 | 最容易写成哪种模板？虚拟问答、数据前置、故事套路还是宏大开场？ |
| 开头任务 | 开头要完成代入、解释、定调、反常、筛选读者还是直接给答案？ |

开头不是为了“好看”，而是为了让读者迅速知道：这篇文章和我有什么关系，为什么值得读下去。

## 二、开头类型库

每篇文章从下面选择 1 种主开头方式，可以混合 1 种辅助方式。不要连续多篇使用同一种开头。

### 1. 直接回答型

适合搜索型指南、政策时间、资格条件、教程类。

写法：先回答读者最关心的问题，再说明本文覆盖范围。

避免：一上来绕故事，拖延答案。

### 2. 具体场景型

适合关系、生活、职场、故事、成长类。

写法：用一个动作、物件、时间、对话或沉默进入问题。

避免：虚构“朋友/后台/群里”作为万能入口。

### 3. 判断先行型

适合观点评论、行业分析、选择建议。

写法：先给一句有边界的判断，再解释这个判断适用于谁。

避免：把判断写成口号或绝对结论。

### 4. 反常切入型

适合已有主流说法但需要修正的文章。

写法：先指出一个和常识不完全一致的现象，再给出解释方向。

避免：为了制造冲突而强行反主流。

### 5. 冲突/选择型

适合决策、职场、教育、产品选择、关系修复类。

写法：把读者放到一个真实选择里，让问题自然出现。

避免：把选择写成夸张戏剧冲突。

### 6. 小事实型

适合政策、行业、科技、趋势、报告解读。

写法：用一个具体、可验证、和当前判断强相关的事实开头。

避免：一上来堆数字或报告摘要。

### 7. 反问/真问题型

适合读者已有困惑的话题。

写法：提出一个真实、具体、读者会承认的问题。

避免：泛泛而问，如“你是否也曾……”

### 8. 物件/意象型

适合关系、生活、故事、文化、个人表达。

写法：用一个物件或反复出现的小动作承载主题。

避免：意象太飘，读者看不出文章要说什么。

## 三、虚拟来源开头规则

以下写法属于高频模板，默认禁用：

- “后台有人问……”
- “群里有人问……”
- “最近很多人问……”
- “每到报名季/年底/开学季，就有人问……”
- “网上很多人都在问……”
- “评论区经常看到……”
- “有朋友问我……”

允许使用的条件：

1. 用户确实提供了真实评论、后台问题、群聊截图或读者提问。
2. 这条提问本身足够具体，不是泛泛的引子。
3. 本文需要从真实读者问题出发，而不是作者找不到开头。
4. 同一任务或同一批文章不能反复使用这种入口。

使用时要具体化：

```text
弱：每到报名季，后台和群里问得最多的一句话就是……
较好：今年国考报名刚开始，很多人真正卡住的不是“要不要报名”，而是发现岗位表里每一项限制都像在筛人。
```

## 四、数据前置规则

数据可以开头，但只适合以下情况：

- 数据本身反常，能改变读者理解。
- 数据是本文要解释的核心问题。
- 数据关系到政策、价格、资格、风险等硬信息。

不适合：

- 情感、关系、生活、随笔类文章。
- 数据只是为了显得专业。
- 数据一出现就需要解释很多口径，拖慢阅读。

更好的方式通常是：先用问题或场景进入，再把数据放到第二段或第三段作为支撑。

## 五、开头候选机制

重要文章至少内部设计 3 个不同开头方向：

1. 一个直接清楚的版本。
2. 一个更有场景或画面感的版本。
3. 一个更有判断或反常感的版本。

然后选择最适合平台、体裁和文章气质的一个。不要把 3 个版本都展示给用户，除非用户明确要选择。

评估标准：

| 维度 | 问题 |
|---|---|
| 新鲜度 | 是否避开常见模板？ |
| 贴题度 | 是否直接服务本文主题？ |
| 读者关系 | 读者能否马上知道和自己有关？ |
| 信息量 | 第一段是否有有效信息，而不是空转？ |
| 可信度 | 是否没有虚构读者、经历或数据？ |
| 延展性 | 是否能自然引出正文主张？ |

## 六、不同体裁的开头建议

| 体裁 | 推荐开头 | 慎用开头 |
|---|---|---|
| 政策/考试/硬信息 | 直接回答、小事实、判断先行 | 虚拟后台提问、故事铺垫 |
| 实用指南 | 读者任务、选择冲突、直接回答 | 宏大背景、数据堆砌 |
| 观点评论 | 判断先行、反常切入、冲突切入 | “最近很多人讨论”、空泛设问 |
| 情感关系 | 具体场景、动作细节、物件意象 | 数据前置、专家前置、后台有人问 |
| 故事人物 | 具体场景、选择瞬间、动作细节 | 先总结人物品质 |
| 产品工具 | 使用场景、选择困境、小事实 | 广告式卖点、功能列表 |
| 文化教育 | 真问题、概念误区、具体例子 | 抽象大词、文学化铺陈 |

## 七、输出要求

在大纲前内部确认：

```markdown
## 开头设计
- 读者入口：
- 主开头类型：
- 备选开头类型：
- 禁用套路：
- 推荐开头策略：
```

如果用户要求直接出稿，也必须在内部完成这一步。

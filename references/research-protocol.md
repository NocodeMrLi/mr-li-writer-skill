# 检索与事实验证规范

## 一、先拆任务

检索前先写出：

- 第 0 步选题诊断中的推荐方向、备选方向和不建议方向
- 文章体裁和证据密度：高、中、低或极低
- 文章模式和目标读者
- 需要回答的 3-5 个问题
- 主搜索词、次级搜索词和用户自然问法
- 哪些信息是时效敏感的
- 哪些信息必须完整，哪些信息允许抽样

如果任务是从标题、核心想法或模糊灵感开始，先执行 `references/ideation-protocol.md`，完成至少两轮检索判断后再进入事实研究。

进入事实研究前，先执行 `references/genre-structure-protocol.md`。证据密度为低或极低时，只检索最小必要背景，不要把检索结果反向塞满文章。

不要把“全网搜索”理解成搜得越多越好。目标是找到能支撑文章判断的最小充分证据集。

### 用户资料是种子资料

用户提供的链接、文件、截图、原文或摘要，只算种子资料，不算完整资料搜集。它们的用途是帮助理解任务、发现线索、保留用户关心的问题，而不是替代外部核验。

默认规则：

- 除非用户明确说“只基于我给的资料写 / 不再外查 / 不要联网”，否则必须围绕主题继续检索最新、权威、最匹配资料。
- 政策、考试、报名、资格、价格、产品更新、行业新闻、法律、医疗、金融等硬信息，必须补官方/权威来源和最新核验。
- 用户给的公众号文章、媒体稿、机构汇总或截图，不得直接改写成正文并在文末写“本文为二创整理”。这属于读者端生产口径暴露。
- 如果宿主没有检索/联网能力，先告知用户只能做“基于已给资料的有限整理/改写”，获得明确同意后再继续。

最小来源组合：

| 来源层 | 必做动作 | 任务状态字段 |
|---|---|---|
| 用户种子资料 | 解析用户给的链接/文件/截图，提取事实、观点、疑点和不可用内容 | `user_seed_sources`、`user_sources_checked` |
| 官方/权威来源 | 核对官网、监管、公告、原始报告、企业原始发布或权威资料 | `official_sources_checked` 或 `official_sources` |
| 最新核验 | 判断信息是否仍有效，记录信息截至日期 | `freshness_checked` |
| 独立交叉核对 | 冲突或高风险信息至少补一个可靠交叉来源 | `independent_crosscheck_checked` 或 `independent_sources` |
| 来源组合说明 | 说明用户资料、官方资料和交叉资料如何共同支撑正文 | `source_mix` |

进入正文、排版或交付前，任务状态必须保留 `original_prompt`、`topic` 或 `brief`，并运行：

```bash
python3 scripts/validate_research_scope.py <任务状态.json> --phase draft
python3 scripts/validate_task_intake.py <任务状态.json> --phase draft
```

`validate_task_intake.py` 会在 `draft/layout/delivery` 阶段自动调用资料范围校验。任何智能体、模型或宿主都不能通过不记录原始任务、不记录用户链接、只填确认项来绕过资料搜集。

## 二、关键词与搜索意图

围绕以下角度设计关键词组：

1. 定义、背景和用户问题
2. 最新政策、时间、价格或流程
3. 数据、案例和一手材料
4. 争议、反方和限制条件
5. 用户执行时的错误与障碍

搜索词带年份只适用于时效性主题。不要为了看起来专业而给所有主题强行添加年份。

## 三、来源分级

| 等级 | 来源 | 用法 |
|---|---|---|
| A | 政府、监管部门、官方统计、原始论文、企业原始公告 | 关键事实首选 |
| B | 权威研究机构、专业媒体、行业协会、一手访谈 | 背景、行业解释和交叉验证 |
| C | 垂直媒体、社区、个人文章 | 只用于发现问题、用户语言和舆情 |
| D | 无来源、标题党、营销软文、内容农场 | 不作为事实依据 |

来源等级不是质量的唯一标准。还要检查发布时间、研究口径、适用范围、利益关系和是否直接支持当前论点。

### 利益相关来源

若第三方机构通过培训、辅导、认证、课程、咨询或同类服务从文章主题中直接获利，它属于商业相关来源，不得因为资料整理得完整就获得与官方来源相同的正文露出。

- 官方资料能覆盖的事实：只用官方口径，第三方资料仅作内部交叉核对。
- 第三方资料补充了官方未汇总的信息：先逐项回到官方页面核对；仍需概括时，正文写“相关机构公开汇总”，不并列培训机构名称。
- 文章本身评测、比较或介绍该机构：可以显名，但必须说明它与主题的直接商业利益和材料边界。
- 不能核对到官方依据：降低结论强度或标为待核实，不以培训机构汇总替代官方结论。

示例：

- 不推荐：“数据来自全国软考报名平台当前页面及 51CTO、希赛网公开汇总。”
- 推荐：“数据来自全国软考报名平台当前页面及相关机构公开汇总。”

## 四、按风险核验

- 政策、法律、医疗、金融、价格、报名时间和资格条件：优先一手来源，并注明有效时间。
- 统计数字：核对样本、分母、时间范围、定义和是否被二次解读。
- 新闻事件：区分发生时间、报道时间和后续变化。
- 独特官方事实：只有一个权威来源时可以采用，但标注“单一官方来源”，不要机械拼第二个来源。
- 观点和建议：不要求伪装成事实，但要明确其依据和边界。

两个来源冲突时，保留冲突、解释选择理由；无法判断时降低表述强度或不写。

## 五、检索降级协议

当一手来源不可达、检索工具失效、官网正文为空或搜索结果跑偏时，按固定顺序降级：

1. 官方一手来源：官网、政府站点、监管部门、官方公告、原始 PDF 或图片公告。
2. 官方渠道转载：官方公众号、官方服务平台、官方合作渠道。
3. 权威第三方汇总：垂直机构、行业站点、专业媒体。
4. 搜索引擎结果摘要：仅用于发现线索和暂时提示，不作为强结论依据。

一手来源不可达时，禁止把第三方汇总伪装成官方口径；查不到的字段明说“缺口”，不硬凑、不凭记忆补来源。

工具失效时按以下方式处理：web_search 失效时改用直连官网或搜索引擎结果页；官网正文 JS 渲染不可读时，尝试公告图片 OCR、PDF 下载链接、页面静态资源或站内搜索；多次失败后停止重试，按降级路径处理并告知用户当前信息可信度上限。

如果用户提供了种子资料但外部检索工具不可用，不能默认进入完整写作。必须先说明限制，并让用户确认是否接受“只基于已给资料”的有限整理。用户未确认前，不进入正文、排版或交付。

降级后的标注格式：

```text
（来源：XX 第三方汇总，以官方为准；信息截至 YYYY-MM-DD）
```

动态信息必须附信息截至日期。

## 六、对外来源口径

检索、核验和资料整理过程是内部工作，不写进读者可见正文。正文可以说明信息时点、来源属性和核验边界，但不能暴露后台动作。

禁止出现在正文、标题、图注、注释、预览页可见文字中的表达：

- “2026 年 8 月抓取”“页面抓取结果”“爬取到的信息”“采集数据”
- “检索结果显示”“搜索结果显示”“本次检索发现”
- “通过爬虫/脚本/工具整理”“由 AI/模型生成”“提示词输出”
- “资料清洗后发现”“根据抓取页面”“本次采集口径”
- “本文为二创整理”“基于原文改写”“基于链接改写”“基于素材二次创作”

推荐改写：

- “2026 年 8 月抓取” -> “信息截至 2026 年 8 月”
- “PMI 官网页面当前抓取信息” -> “据 PMI 官网当前页面信息”
- “检索结果显示” -> “公开资料显示”或“目前公开可查的信息显示”
- “爬取到的报名信息” -> “官方页面列出的报名信息”
- “本次整理发现” -> “对照官方口径可以看到”
- “本文为二创整理” -> 直接删除；需要说明边界时放在交付说明，不放入正文

原则：让读者看到的是“你依据什么判断”，不是“你怎么把资料拿到手”。如果必须说明核验动作，把它放在交付说明或内部备注中，不放入正文。

正文来源说明还要避免无关商业背书。与主题存在直接商业利益的培训、辅导、认证或服务机构仅用于内部交叉核对时，不显名，统一使用“相关机构公开汇总”等中性口径；但不得借中性口径把未经官方核验的数据伪装成权威事实。

## 七、事实台账

写作前内部维护：

| 论点/事实 | 类型 | 来源 | 发布日期 | 适用范围 | 可信度 | 是否采用 | 备注 |
|---|---|---|---|---|---|---|---|
| ... | 事实/推理/假设 | URL | YYYY-MM-DD | 地区/人群/时间 | A-D | 是/否 | ... |

高证据和中证据文章中，每个核心论点至少要有一个可追溯依据。低证据和极低证据文章中，核心判断也要有依据，但依据可以是用户提供的真实素材、具体场景、行为细节、逻辑推演或清楚标注的作者观察，不强制每个判断都对应外部 URL。

多个来源只在能增加可靠性或解释冲突时使用。不要为了让文章显得专业而给低证据体裁机械堆来源。

## 八、内容适配闸口

逐条判断：

1. 这条资料是否回答本文的问题？
2. 是否支持当前句子的强度？
3. 是否过时、超出地区或人群范围？
4. 是否包含广告、利益关系或未经证实的转述？
5. 是否会让读者误以为推测是事实？

资料不足时有三种合法处理：

- 继续检索；
- 降低结论强度；
- 明确写成待验证的推演。

不得用低质量来源补齐文章气势。

## 九、实体和隐私

默认不做静默脱敏。品牌、公司、产品和人物名称是否保留，按照任务的实体模式处理：

- `normal`：正常使用，并保证事实准确。
- `clean`：删除推广性内容，但保留必要实体。
- `anonymous`：只对用户明确指定的词做替换。
- `profile`：允许主体名称、身份和经历出现。

来源透明不等于给商业相关机构做正文露出。官方、论文、监管公告等关键来源应保留名称与原始 URL；直接从主题获利的培训/服务机构若仅作辅助核对，正文不显名，参考资料中也优先替换为可验证的一手来源。若文章本身以该机构为对象，则按 `profile` 或评测语境显名并披露利益关系。

## 十、文末引用

正文实际使用的数据、政策和关键事实，统一放入：

```markdown
## 参考资料
### 一手来源
1. 机构名：《报告/通知名》，发布时间，原始 URL

### 第三方来源
1. 机构名：《页面/文章名》，发布时间或访问日期，原始 URL（经 XX 汇总核对，以官方为准）

### 未核验信息
1. 信息项：待核实，以官方最新通知为准。
```

只列实际用到的来源。注明数据时点、地区、样本或“以官方最新页面为准”等必要限定。高证据文章必须优先列一手来源；动态信息（报名时间、价格、政策窗口等）附“信息截至日期”。

研究资料服务于内容，不要把正文写成 URL 清单，也不要把来源类别伪装成具体机构。

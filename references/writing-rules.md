# 深度文章写作规范

## 文章结构（柔性框架，禁止套模板）

下面只是"思考地图"，不是要你机械套成一个固定骨架。真人写文章，各部分比重是流动的：有时开头铺很长，有时一句就收；有时证据堆得密，有时只讲一个故事。核心要求只有一句——**有问题、有证据、有观点、有行动**，顺序和比重你自己拿捏，别去凑固定配比。

### 开头铁律（最重要的一条，违反即判 AI）

- **第一段（甚至前两段）绝对禁止**：①以"根据 XX 报告显示""数据显示"开头 ②把核心结论/判断直接喊出来 ③堆 3 个以上数字
- 正确做法是"把读者带进一个具体情境"，让他先产生疑问或共鸣，再自然引出话题。结论要让它"长"出来，不是"砸"下来——放到中后段，用证据托着慢慢出来。
- 可任选一种开头手法（不要全堆上）：
  1. **场景切入**：一个具体的画面、时刻、对话，让人"看见"而非"被告知"
  2. **反常/矛盾**：抛出一个和直觉打架的现象，读者会忍不住想"凭什么"
  3. **替读者问出真问题**：把他没说出口的困惑直接问出来
  4. **个人体感**：你或身边人真实的感受、吃过亏的经历，带主观温度
  5. **共识型锋利判断**：仅限读者会立刻点头、且你已有充分证据支撑的判断，不是凭空下结论

### 结构反套路（避免"高度规整"的 AI 指纹）

- **比重不均匀才像人**：允许某个小节只有一句话，也允许某个小节展开 800 字；别硬凑"开头 X% / 事实 Y% / 结尾 Z%"的配比
- **小标题不要一个模子**：别每个标题都 4 个字、都"名词+动词"；有的可以是一句口语、一个反问、甚至半句话
- **允许闲笔和跑题**：真人写到一半会插一句吐槽、一个联想、一段自我怀疑，这种"不整齐"恰恰是活气
- **证据分布错落**：不要每个观点都配一模一样的"数据+案例"对称结构；有的段纯讲理，有的段纯讲故事
- **收尾不唯一**：可以一句话收，也可以留个开放式问题，或一个反差画面，不必每次都"互动钩子"

## 情感与声音（反模式化的关键）

模式化的根因是"不敢表态、不敢带情绪、不敢用'我'"。真人写作是有脾气的，文章要让人读出"坐在这写字的是个人"。

- **敢下主观判断**："说实话，这条政策对普通考生不太友好"比"该政策引发广泛讨论"更像人。判断可以尖锐，但要有证据兜底（呼应"新颖角度有据"）
- **情绪要具体，不要标签化**：不写"令人焦虑"，写"报名截止前三天，群里每天几百条'我到底报哪科'的提问"——用画面承载情绪，比形容词有力十倍
- **允许矛盾和不确定**："我一边觉得该考，一边又怀疑这证到底值不值"——混合情绪比单向度更可信
- **'我'可以出现，但别滥**：用在交代信息来源（"我翻了三份通知"）和表达真实态度（"我个人不太推荐"）时最自然
- **锋利短句砸点**：在一段铺陈之后，用一句很短、很硬的话收尾，制造节奏落差
- **拒绝平均用力**：全文不能每个段落情绪强度一样；要有克制处，也要有释放处，像呼吸

## 新颖角度，但要有据（核心能力）

用户要求文章能从特别的角度说出不同看法，但看法不能天马行空，要站得住脚。做法：

1. **先抓主流叙事**：动笔前用一两句话总结"大家通常怎么看这个事"（主流观点/共识/常见标题）
2. **再找差异化角度**：从下面方向里挑一个，但必须能回到检索到的证据：
   - **Hidden angle（被忽略的角度）**：主流没讲、但资料里有支撑的侧面。例：大家都写"AI 多厉害"，你写"为什么四成多人用 AI，但真用出效果的还是少数"——用 71.7% 效率提升 vs 近五成"有要求无方向"的数据撑住
   - **视角转化**：换主人公/换时间尺度/换利益相关方看同一件事
   - **反直觉但有据**：提出一个和常识相反的判断，但用数据或案例兜底，并诚实说明边界
3. **推理要透明**：新颖观点后面，用"因为……数据显示……所以……"把推导链亮出来，让读者能跟着走
4. **不硬凹**：如果资料撑不起差异化角度，宁可走扎实的主流角度，也不要为了新奇编证据。宁可平，不可假。

## 用户核心想法输入（协作机制）

用户除了给主题和参考资料，也可以直接抛自己的核心想法，甚至天马行空的念头。处理方式：

- **照单全收，不评判**：用户说的"我觉得……""我有个疯狂的想法……"都先记下来，作为文章的种子角度
- **AI 负责搜证落地**：用检索去验证用户的想法——哪部分有数据支撑（采纳并放大）、哪部分没依据（明确说"这个目前没有公开数据支持"，但不删掉用户的原意，可作为"一种可能性"讨论）
- **天马行空部分怎么写**：可以保留为"一种大胆的推演"，但必须和"已验证事实"分开标注，不让读者混淆猜测与结论
- 最终文章是"用户的想法 + AI 的查证与成文"的合体，而不是 AI 自说自话

## 关键权威信息必须完整，非必要不举例

用户对某些硬信息是"查全查准"心态，这类信息必须完整呈现，不能用"随便举几个"糊弄。规则：

1. **必须完整的情况**：考试报名时间（按地区）、考试科目清单、政策条款条目、报考资格条件、可报名地区/批次等。这类信息只要网上有官方公布，就应该搜全并列表呈现。
2. **允许取样的情况**：海量数据类信息（如招聘平台统计、大型调研报告、行业整体数据），可选取代表性数据，但必须说明口径和样本范围，且不能是用户最关心的核心信息。
3. **不确定是否完整时**：先搜一轮，如果明显还有大量未覆盖项，继续检索补全；补全后仍过长的，可用折叠表格或分地区分组呈现，但不能偷偷省略成"例如"。
4. **已公布但找不到全部的地区**：诚实说明"截至搜索时，已公布报名时间的地区如下"，并标注"其他地区请持续关注本地软考办/人社厅通知"。

## 增强技巧（按需取用）

- **共情点设计**：开头先接住读者的真实情绪（焦虑/迷茫/不甘），再给信息，比直接讲道理更立得住
- **金句**：全文埋 1-3 句能脱离上下文传播的短句（锐利、有画面、不鸡汤），放在小节收尾或转折处
- **情感曲线**：像安排电影节奏一样安排文章起伏——钩子提神、事实压住、分析拉升、行动给希望，别全程一个调
- **互动钩子（公众号适用）**：结尾抛一个让读者想评论的问题，如"你身边用 AI 的人多吗？评论区聊聊"

## 版面规则

- **短段落**：每段不超过 4 行，一段一个意思
- **分隔符**：章节之间用纯 ASCII（如 `=====`），不用特殊 Unicode 符号（复制到编辑器易乱码）
- **表格优先**：对比、清单、流程、数据类信息一律用 Markdown 表格呈现
- **列表适度**：并列项超过 3 个用列表；但禁止"加粗标题+冒号"的机械列表（见 humanize-rules.md）
- **小标题**：用 ## / ###，标题口语化、带信息量，不用"一、二、三"公文式编号

## 洁净内容规则（红线）

- 禁止出现任何品牌名、产品名、公司名、人名（公众人物作为新闻主体且用户明确要求时除外）
- 禁止出现**素材里夹带的个人 IP / 博主名 / 网红名 / 个人品牌**（提取种子文档和读检索结果时主动抹掉，只留观点与事实）
- 禁止任何形式的推广：课程、机构、社群、微信号、二维码引导、回复关键词领资料
- 禁止编造引用：不虚构"某专家说""报告显示"，所有引用必须来自检索记录
- 表达来源时用类别指代："官方通知""某招聘平台 2025 年报告""业内人士透露"
- **文末参考资料段允许放官方来源 URL**，这是唯一可以出现链接的位置

## 论证质量

- 每个核心观点至少配 1 个具体证据（数据/政策原文/真实案例）
- 数据要给出量级和口径（"约 30%""2025 年报考人数超 500 万"），不用模糊词堆砌
- 敢于给明确结论和推荐排序，不要"各有千秋""视情况而定"式和稀泥
- 承认不确定性：证据不足时直接说"目前没有公开数据"，这比编造更可信

## 文末引用格式（参考资料段）

必须在文章结尾以 Markdown 列表形式给出，每条包含：

```
1. 机构名：《报告/通知名》，发布时间，原始 URL
2. 机构名：《报告/通知名》，发布时间，原始 URL
```

- 政府公告、考试安排、报名通知类来源必须给原始政府门户网站 URL
- 数据报告类给发布机构官网 URL
- 若同一事实被多个官方来源重复确认，可只列最具代表性的 1-2 条并说明"多省通知一致"

## 目标读者适配

- 写给备考人群：强调时间节点、条件门槛、选择建议
- 写给 PM/产品人群：强调职场影响、能力迁移、落地路径
- 写给泛职场人：强调成本收益、风险、可执行的第一步

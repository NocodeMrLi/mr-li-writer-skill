# 内容创作与平台适配规范

## 总原则

文章必须同时具备：问题、证据、判断和行动。**去 AI 味优先于 SEO、结构和排版**。不要为了关键词密度、标题刺激或形式上的“不规整”，牺牲自然表达和真实边界。

正式写作前必须先确认选题诊断结论：原方向是否值得写、采用哪个升级角度、哪些常见写法要避开、哪些判断必须降级或补边界。没有完成选题诊断时，不要直接生成完整正文。

正式写作前还必须按 `genre-structure-protocol.md` 确认文章体裁、结构变体和证据密度。结构和证据必须为文章性质服务，不要让所有文章都变成同一种报告式论证。

重要平台文章还应按 `high-impact-writing-protocol.md` 做主题升维、记忆点设计和反平庸检查。但高完成度不等于文学化：不能为了文采、隐喻、余味或审美感，牺牲普通目标读者的清晰理解和阅读意愿。

文章开头必须按 `opening-design-protocol.md` 单独设计。不要默认使用“后台有人问”“群里有人问”“每到这个时候网上有人问”等虚拟来源开头，也不要把所有文章都写成数据前置。虚拟化开头不是完全禁止，但必须真实、具体、服务当前文章；开头同质化、假场景、泛季节、宏大背景、空泛设问和定义开场都要主动避开。

## 一、按内容模式选择结构

### `research-explainer`

适合政策、行业和复杂概念：

问题场景 -> 核心结论 -> 证据拆解 -> 影响与边界 -> 读者行动

### `practical-guide`

适合教程、清单和避坑：

读者任务 -> 判断标准 -> 操作步骤 -> 常见错误 -> 检查清单

### `opinion-analysis`

适合观点、争议和用户核心想法：

主张 -> 主流看法 -> 事实证据 -> 推理链 -> 反方意见 -> 作者判断

### `story-profile`

适合人物、案例和故事：

具体场景 -> 冲突 -> 人物/对象选择 -> 关键事实 -> 转折 -> 主题判断

结构只是导航，不要每篇文章都套同一顺序。内容模式只能决定大方向，不能替代体裁识别。比如 `opinion-analysis` 可以是行业评论，也可以是亲密关系观点；前者可用较高证据，后者应以场景和关系判断为主。

## 二、按体裁决定证据密度

写作前先选择证据密度：

| 密度 | 适合内容 | 写法 |
|---|---|---|
| 高 | 政策、法律、医疗、金融、行业报告 | 一手来源、数据、口径、时间和边界必须清楚 |
| 中 | 工具、职场、教育、观点、产品分析 | 数据、案例、反方和逻辑搭配，不每段都引用 |
| 低 | 情感、关系、生活、成长、故事 | 少量背景即可，重点是场景、动作、互动和判断 |
| 极低 | 随笔、观察、关系短文、个人表达 | 可以没有数据，不强行专家背书 |

数据说明要有边界，但不是每类文章都必须大篇幅数据论证。比如“夫妻之间的保鲜剂”这类文章，可信度主要来自具体生活细节、互动动作和克制判断，而不是调查数字和专家术语。最多使用一个背景性事实；没有必要时可以完全不用数据。

## 三、结构变体

根据体裁选择主结构和辅助结构：

- 问题解决型：读者任务 -> 判断标准 -> 步骤 -> 常见错误 -> 检查清单。
- 场景关系型：生活场景 -> 关系变化 -> 关键误区 -> 具体动作 -> 温和判断。
- 观点修正型：常见看法 -> 成立条件 -> 失效场景 -> 更准确判断 -> 读者行动。
- 事实解释型：最新事实 -> 背景 -> 影响对象 -> 关键边界 -> 下一步。
- 故事特写型：具体场景 -> 冲突 -> 人物选择 -> 事实嵌入 -> 转折 -> 主题判断。
- 对比决策型：选择困境 -> 选项拆解 -> 适合人群 -> 成本风险 -> 推荐路径。
- 观察随笔型：一个观察 -> 几个细节 -> 心理/关系变化 -> 留白式判断。
- 平台轻清单型：身份/场景 -> 关键提醒 -> 短清单 -> 易错点 -> 收藏/行动。

每篇文章必须选择一种主结构和一种辅助结构。不要默认使用“三个原因 + 三个方法 + 总结”。

## 四、开头选择

根据任务选择一种：

- 场景切入：适合故事、人物、职场和生活问题。
- 直接回答：适合搜索型实用指南和政策时效内容。
- 反常事实：适合有可靠证据的观点文章。
- 真问题：适合读者已经有明确困惑的主题。
- 明确判断：适合评论和决策内容，但必须马上说明判断范围。

不要强制所有文章延迟结论，也不要强制所有文章用故事开头。核心要求是第一段有信息、有画面或有问题，不要用模板化的“随着……发展”开场。

开头禁用默认套路。以下只是代表，不是完整清单：

- “后台有人问……”
- “群里有人问……”
- “最近很多人问……”
- “每到报名季/年底/开学季，就有人问……”
- “网上很多人都在问……”
- “评论区经常看到……”
- “有朋友问我……”
- “随着……发展……”
- “在当今社会……”
- “你是否也曾……”
- “所谓……就是……”
- “朋友小 A 最近……”

这些写法只有在用户提供真实提问、评论或截图，并且该提问足够具体时才可使用。即便使用，也要具体化，不能作为万能开头。
同一个主题在不同任务下也要重新设计开头，不允许只是替换几个关键词复用同一入口。

## 五、观点和证据

写作前为每个核心观点标注：

| 类型 | 写法 |
|---|---|
| 已验证事实 | 自然带出来源和时间 |
| 多条事实推导 | 展示“事实 -> 推理 -> 判断” |
| 用户假设 | 标记为推演或可能性 |
| 作者观点 | 明确这是判断，并说明依据 |
| 建议 | 给出适用对象、成本和限制 |

不要把用户的大胆想法“照单全收”为事实。可以保留它的方向，但必须给出证据状态。

数据和专家只能在能支撑判断、纠正常见误解或帮助读者决策时使用。不能为了让文章显得高级，在情感、生活、随笔和故事类文章里硬塞“研究表明”“专家指出”。

## 六、写出差异化

优先从以下方向选择一个：

- 被忽略的利益相关方
- 被忽略的时间尺度
- 同一事实对不同人群的不同影响
- 主流结论成立的条件
- 看似矛盾但有证据的结果
- 用户真正要解决的问题，而不是表面问题

差异化不是故意反常。资料无法支撑时，选择准确的主流角度。

## 七、自然表达

- 用具体对象、动作、时间、选择和后果替代抽象形容词。
- 允许有态度，但不要把情绪写成口号。
- 允许有审美，但不要把平台文章写成文学作品、散文随笔或漂亮但难转述的文本。
- 不虚构第一人称、采访、亲身经历或作者身份。
- 允许短句、停顿和自然重复，但不故意制造错别字或无关闲笔。
- 小标题有信息量即可，不要求字数和句式整齐。
- 每段只承载一个主要动作或判断，必要时拆段。
- 对比、流程和硬信息使用表格或列表，但不要把全文写成表格。
- 情感和关系类文章优先写对话、沉默、重复的小事、被忽略的动作和选择后果，不要写成“专家建议夫妻要加强沟通”的说明文。
- 主题升维要回到读者能理解的处境、选择和动作，不能升到空泛宏大词。

## 八、实体、推广与引用

默认禁止未经授权的广告、导流、课程销售、二维码、虚假推荐和夸大承诺。

品牌、公司、产品和人物是否出现，按任务模式决定：

- `normal`：允许正常提及和引用。
- `clean`：避免推广性提及，但保留必要事实。
- `anonymous`：对用户指定的个人或机构做脱敏。
- `profile`：允许人物、机构和案例作为文章主体。

不要因为“去个人 IP”而删除必要的新闻主体或来源信息。文末只列实际使用的资料，并保留原始 URL。

## 九、关键硬信息

报名时间、地区、科目、政策条款、资格条件、价格和流程等信息，要么完整呈现，要么明确说明覆盖范围和截止时间。

海量数据可以抽样，但必须写清样本、口径、时间和抽样理由。找不到完整信息时，明确告诉读者哪里未确认。

## 十、平台适配

| 平台 | 内容重点 | 标题方向 | 排版 |
|---|---|---|---|
| 公众号 | 观点、解释、完整论证 | SEO 兼顾可读性 | `minimal-gold` / `editorial-red` / `magazine-warm` / `business-blue` |
| 小红书 | 场景、清单、经验和选择 | 身份/问题/结果 | `fresh-green` / `card-modern` / `note-paper` |
| 知乎 | 证据、边界、反方和方法 | 问题/比较/判断 | `ink-scholar` / `business-blue` / `editorial-red` / `mono-lab` |
| 通用 SEO | 搜索意图和问题闭环 | 核心词 + 明确承诺 | `minimal-gold` / `business-blue` / `note-paper` / `calm-cyan` |

平台改写不能只是删字。要重写开头、段落节奏、标题、结尾动作和信息密度。

## 十一、排版主题选择

最终生成 HTML 时，默认使用 `build_html.py` 的 `auto` 主题选择：先根据内容模式、发布平台、标题和正文关键词判断合适的主题池，再从候选主题中随机选择一个。不要每次都固定使用同一个主题。

主题匹配建议：

| 主题 | 适合内容 |
|---|---|
| `minimal-gold` | 公众号深度文、通用长文、稳重观点 |
| `business-blue` | 政策解读、行业分析、数据报告 |
| `magazine-warm` | 故事、人物、案例和长阅读 |
| `fresh-green` | 小红书、知乎轻阅读、生活和成长类 |
| `ink-scholar` | 知乎深度、文化、教育、思辨类 |
| `card-modern` | 产品文、小红书卡片感内容、轻量清单 |
| `editorial-red` | 评论、争议观点、社会议题和主张型文章 |
| `calm-cyan` | 科技、AI、工具、效率和方法论 |
| `note-paper` | 实用指南、步骤、清单、避坑和复盘 |
| `mono-lab` | 产品分析、技术说明、极简报告 |

如果用户不喜欢自动选择的风格，可以重新生成一次，或用 `-t <主题名>` 指定主题。

## 十二、交稿前检查

- 标题承诺是否被正文兑现？
- 开头是否为当前文章单独设计？有没有落入虚拟来源套话、泛季节开头、假场景、空泛设问、定义开场、数据前置惯性或宏大背景开场？
- 搜索关键词是否自然出现，而不是堆砌？
- 每个核心判断是否有证据、推理或明确的观点标记？
- 主题升维和记忆点是否让文章更清楚有力，而不是更文学、更飘、更难懂？
- 证据密度是否匹配文章体裁？有没有把情感、生活、故事类文章写成数据报告？
- 文章结构是否和上一类文章过于相似？有没有机械“三点原因 + 三点建议”？
- 是否出现虚构第一人称、伪引用或未经证实的数字？
- 是否删掉了模板化套话和重复结构？
- 读起来是否像一个认真思考的人，而不是搜索摘要？
- 普通目标读者是否愿意读完，并能转述核心判断？
- 文章是否给目标读者一个明确的下一步？
- HTML 主题是否和文章气质匹配？如果不匹配，是否已更换主题重新生成？

交付前必须完成至少两轮 AI 味检查和修改：

1. 第一轮：删除套话、虚拟来源开头、重复结构、证据腔、无来源第一人称和不匹配的数据/专家。
2. 第二轮：朗读式重写，检查开头新鲜度、段落节奏、结尾余味、可转述记忆点和普通读者可读性。

只检查不修改不算完成。检查结果不是交给用户看的“待优化建议”，而是交付前必须执行的修正文任务清单。每发现一个 AI 味问题，都要直接改正文、改结构、改开头、改证据表达或改结尾，然后重新检查。两轮后如果仍有明显 AI 味，继续多轮 loop：每轮都要先定位问题，再修改正文，再重新检查。直到不再发现明显 AI 味后才能交付。若因为用户指定原文、必须保留的硬信息或平台格式限制无法完全消除，要在交付时说明残余风险和保留理由。

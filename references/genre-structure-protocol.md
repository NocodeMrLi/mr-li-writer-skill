# 文章体裁、结构变体与证据密度规范

## 目标

不同文章有不同的阅读心理、内容属性和可信方式。正式写作前先结合 `editorial-routing-protocol.md` 判断读者任务，再决定体裁、结构、证据密度、数据比例、专家引用、语言节奏和排版风格。

本规范要解决的问题是：不要把所有文章都写成“开头抛结论 -> 数据/专家说明 -> 三个原因 -> 三个方法 -> 总结升华”。结构单一、证据滥用和节奏过度整齐，都是明显的 AI 腔。

## 一、体裁识别

在写大纲前，先内部记录：

| 字段 | 要回答的问题 |
|---|---|
| 主体裁 | 这篇文章主要是解释、说服、指导、陪伴、叙事、评论还是分析？ |
| 读者任务 | 读者主要是找答案、做选择、避风险、学方法、被理解还是看故事？ |
| 副体裁 | 是否需要混合故事、清单、反方、数据或案例？ |
| 读者状态 | 读者是求答案、求判断、求安慰、求方法，还是求谈资？ |
| 可信来源 | 可信度主要来自数据、事实、经验细节、逻辑、共情，还是场景真实感？ |
| 证据密度 | 高、中、低、极低中的哪一档？ |
| 结构风险 | 最容易写成哪种模板？应该避开什么？ |

体裁不是固定标签。可以组合，但必须有主次。不要让文章同时像报告、教程、鸡汤和观点社论。

## 二、常见体裁与写法

| 体裁 | 适合主题 | 结构重点 | 可信方式 | 数据/专家比例 |
|---|---|---|---|---:|
| `policy-industry` | 政策、行业、报告、趋势 | 变化、影响、口径、边界、行动 | 一手来源、数据、时间范围 | 高 |
| `practical-guide` | 教程、清单、避坑、选择 | 任务、判断标准、步骤、错误、检查 | 可执行细节、案例、必要数据 | 中 |
| `opinion-commentary` | 观点、争议、社会议题 | 主张、主流说法、反方、边界、判断 | 事实、推理、反例、立场 | 中 |
| `relationship-life` | 夫妻、亲密关系、家庭、成长 | 场景、心理、互动、选择、温和判断 | 生活细节、共情、具体动作 | 低 |
| `story-profile` | 人物、案例、故事、经历 | 场景、冲突、选择、转折、主题 | 时间、地点、人物行为、事实嵌入 | 低到中 |
| `product-tool` | 产品、工具、AI、软件、服务 | 使用场景、对比、成本、限制、建议 | 实测材料、功能事实、案例 | 中到高 |
| `culture-education` | 教育、文化、阅读、思辨 | 问题、概念、经验、反例、余味 | 概念解释、例子、适度引用 | 中 |
| `platform-light` | 小红书、轻内容、生活清单 | 身份、痛点、短建议、提醒、收藏点 | 场景感、清单密度、轻判断 | 低到中 |
| `personal-essay` | 随笔、感受、观察、非虚构表达 | 观察、感受、细节、转念、余韵 | 真实边界、细节、声音 | 极低 |

## 三、证据密度档位

| 档位 | 适合文章 | 规则 |
|---|---|---|
| A 高证据 | 政策、法律、医疗、金融、行业报告、数据研究 | 必须使用一手来源或权威来源；数字、时间、资格、价格必须可核验 |
| B 中证据 | 工具测评、职场、教育、观点分析、产品比较 | 数据、案例、反方和逻辑搭配；不要每段都用专家背书 |
| C 低证据 | 情感、关系、生活、成长、故事、轻建议 | 少量背景即可；重点是场景、互动、具体动作和边界 |
| D 极低证据 | 随笔、散文、个人观察、关系短文 | 可以没有数据；禁止为了显得专业而硬塞研究和专家 |

没有数据不等于不可信。对生活、情感、关系类文章，可信度常来自具体、克制、懂人性、有边界，而不是来自“研究表明”。

## 四、结构变体库

下列结构是诊断参考，不是必须套用的模板。可以选择一个主结构和一个辅助结构，也可以让结构直接从材料的时间、因果、选择和问题顺序中长出来。不要为了证明文章有结构而凑齐每个节点。

### 1. 问题解决型

读者任务 -> 判断标准 -> 步骤 -> 常见错误 -> 检查清单

适合教程、指南、职场、工具类。证据服务于执行，不要把步骤写成报告。

### 2. 场景关系型

生活场景 -> 关系变化 -> 关键误区 -> 具体动作 -> 温和判断

适合夫妻、亲密关系、家庭、成长、心理生活类。少用数据，多写行为、话语、沉默、选择和后果。

### 3. 观点修正型

常见看法 -> 它成立的条件 -> 它失效的场景 -> 更准确的判断 -> 读者行动

适合观点评论、行业观察、教育思辨。避免为了反常而反常。

### 4. 事实解释型

最新事实 -> 背景 -> 影响对象 -> 关键边界 -> 下一步

适合政策、行业、新闻后续。时间、地区、口径必须清楚。

### 5. 故事特写型

具体场景 -> 冲突 -> 人物选择 -> 事实嵌入 -> 转折 -> 主题判断

适合人物、案例和故事。事实藏在场景和选择里，不把故事写成资料清单。

### 6. 对比决策型

选择困境 -> 选项拆解 -> 适合人群 -> 成本/风险 -> 推荐路径

适合产品、工具、课程、证书、服务比较。不要写成单边推荐。

### 7. 观察随笔型

一个观察 -> 几个细节 -> 心理/关系变化 -> 留白式判断

适合生活、情绪、文化、关系表达。结尾不强行给方法论。

### 8. 平台轻清单型

身份/场景 -> 关键提醒 -> 短清单 -> 易错点 -> 收藏/行动

适合小红书、轻指南。信息密度高，但论证不宜厚重。

## 五、数据与专家使用规则

数据、报告、专家和研究只能在三种情况下使用：

1. 文章判断离开它们就站不住。
2. 它们能纠正常见误解或提供必要边界。
3. 它们能帮助读者做决策、避风险或理解变化。

以下情况应少用或不用：

- 情感生活类文章中，数据会削弱亲近感。
- 个人随笔和关系文章中，专家话术会让文本显得端着。
- 故事类文章中，连续引用会打断场景。
- 轻平台内容中，过多出处会破坏阅读节奏。

写法要求：

- 数据只写和当前判断直接相关的最小必要部分。
- 专家观点不能替代作者判断。
- 对生活情感类文章，最多使用一个背景性事实或不使用数据。
- 不用“有研究表明”制造权威感；必须能说清研究和当前文章的关系。

## 六、结构去模板化检查

交稿前必须检查：

- 是否所有段落都像“观点 + 数据 + 解释 + 小结”。
- 是否机械使用“三个原因、三个方法、三个建议”。
- 是否所有小标题都是同一种字数和句式。
- 是否每个部分都以“首先、其次、最后”推进。
- 是否结尾固定升华或机械号召。
- 是否为了显得专业而把关系、生活、故事写成报告。
- 是否为了去 AI 味而加入无关闲笔、错别字或伪经历。
- 是否只是从结构库中选了一个模板，却没有让材料决定详略和顺序。
- 是否每段新增事实、动作、区别、推理或后果，而不是重复解释前文。

如果以上问题明显，必须重写结构，而不是只替换词语。

## 七、输出要求

在大纲前输出或内部确认：

```markdown
## 体裁与结构选择
- 读者主任务：
- 主体裁：
- 副体裁：
- 证据密度：
- 推荐主结构：
- 辅助结构：
- 数据/专家使用边界：
- 需要避开的模板：
- 结构是否直接由材料关系生成：
```

如果用户只要最终稿，也必须在内部完成这一步，不要展示冗长过程。

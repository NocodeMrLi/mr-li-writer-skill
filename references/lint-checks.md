# lint 检查项说明

`scripts/lint_article.py` 的输出用于交付前修正文，不是给用户看的问题清单。出现 warning 时，优先直接修改正文、标题、结构或来源表达，然后重新检查。

## 常见检查项

| 检查项 | 规则含义 | 修改方向 |
|---|---|---|
| 模板化开头 | 出现虚拟来源开头、泛季节、宏大背景、定义开场、空泛设问等 | 重写为具体场景、直接结论或当前材料中的真实问题 |
| 读者任务未完成 | 标题承诺、答案、标准、动作或故事变化没有落地 | 根据读者主任务补足真正缺少的内容，不强塞“核心/真正”等提示词 |
| 翻案修辞动作 | 先替读者虚构误解，再用“你以为/其实”“看似/实则”宣布洞察 | 直接给判断和依据；真实的认识变化可结合语境保留 |
| 段落不推进 | 连续段落只换词解释同一观点 | 合并或删除，补事实、动作、区别、反例或后果 |
| 证据密度不匹配 | 数据、专家、来源使用过重或过轻 | 按体裁调整证据：硬信息补来源，关系生活类减少报告腔 |
| 来源缺失 | 使用硬信息但缺少参考资料 | 补一手来源、第三方来源或降级说明 |
| 后台动作暴露 | 正文出现抓取、爬取、采集、检索结果、AI 生成、模型输出、提示词、脚本整理等过程词 | 改成读者口径：信息截至、据官网当前页面、公开资料显示、以官方最新通知为准 |
| 二创口径暴露 | 正文出现“本文为二创整理”“基于原文改写”“基于链接整理”等生产口径 | 删除这类说法；若确实只用用户资料，边界放在交付说明，不放进读者正文 |
| 商业来源露出 | 把与主题存在直接商业利益的培训、辅导、认证或服务机构名称写成数据背书 | 优先改用官方来源；仅作辅助核对时写“相关机构公开汇总” |
| 排版内部标签 | 读者端出现“公众号排版”“深度文章”“内容创作 Skill”等生产标签 | 改成文章主题标签，或直接删除 |
| 章节编号/目录 | 多章都显示 01，或目录标题重复、错配 | 按 `##` 顺序重建 01/02/03，并逐章核对标题 |
| 卡片溢出 | 多列卡片、目录或提示框中文字越界、裁切、挤压 | 缩短非关键信息，或增加宽高、改横向滚动/单列，保持自然换行 |
| 长段落 | 多个段落过长，阅读节奏像报告或论文 | 拆段，让每段只承载一个动作、事实或判断 |
| 小红书原生度 | 标题过长、emoji 不足或过多、标签数量不对、缺少适合/避坑/判断标准模块 | 改成短标题、短段落、收藏型清单和 6-10 个话题标签 |
| 公众号腔/报告腔 | 过多铺垫、空泛总结、机械三点结构 | 用当前文章的材料重组结构，减少万能句式 |

## 使用建议

- 查询/指南型任务至少做一轮 lint 与人工表达检查。
- 观点/故事型和重要平台文章至少做两轮 AI 味检查与修改。
- 小红书必须带 `--platform 小红书 --mode xiaohongshu-note`。
- 使用时间、价格、政策、报名、资格等硬信息时，加 `--require-sources`。
- 看到后台动作暴露 warning 时，不要把 warning 交给用户当解释，先直接重写正文并复查。
- 用户提供文件、链接或截图时，不要只解析用户资料后写成二创；硬信息先补官方/权威来源和最新核验。
- 看到商业来源露出、编号错乱、内部标签或卡片溢出时，同样先修正文/HTML并重新检查，不把问题版本作为最终交付。
